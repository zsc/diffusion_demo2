已修问题

  • VQ loss 尺度：旧 reconstruction 是逐图像素和，VQ loss 是均值。48px 系数相差 6912，96px 为 27648。新默认两者均值；vq_recon_reduction=sum保留旧对照。VAE ELBO 保持原求和约定，commitment 权重方向原本正确。
  • 空间容量与原生 96px：解除固定 4×4 / 48px。默认两层 hidden 时，VAE 自然网格为 48→6、96→12；VQ 为 48→12、96→24。大网格不改变卷积权重形状，init_checkpoint严格继承权重；必须用真实目标分辨率数据并微调。VAE decoder 仍有最终双线性插值，增加上采样层是后续架构对照。
  • 死参数：VAE 的 down_mu/down_logvar 从未参与 forward，已移除。它们也会破坏默认 DDP 的梯度归约；旧 state-dict 仅忽略这四个已知冗余 tensor，其余键仍严格检查。
  • VQ 大 batch 内存：FP32 最近码查询改为分块、no_grad；保留 STE 和 codebook/commitment 梯度。新增使用代码数/困惑度；此短程实验仍只用了 128 个码中的少数，后续需检查码本更新和初始化。
  • 评估与数值：CLI 统一核心训练器、固定留出集；停止把 Gaussian latent 直送 VQ decoder 当生成测试。GAN 训练用 logits/softplus；预览不再根据像素最小值猜归一化范围。
  • 16 GPU 入口：同一训练器支持 DDP，batch_size 表示全局 batch；分布式采样每轮打散、丢弃不完整全局 batch、只由 rank 0 验证和保存。日志计实际看图量/更新次数。使用每 rank BatchNorm、rank-0 running buffers；分布式 GAN 暂不支持。

验证：31 项测试通过，包括 CPU 双进程、连续两轮的 VAE / VQ-VAE 训练；原生 96px VQ-VAE→DiT→采样与旧 checkpoint 严格加载均已覆盖。后续 16 GPU 验证已完成，结果见更新报告。代码包已暂存 gateway 的 ~/d/try_cluster/diffusion_vae_audit_20261025.tar.gz，SHA256 与本地一致。

结合 JiT 的下一轮实验

  1. 在 1×16 GPU 上先复核这组 2×2 对照，再做 96px 继承与从零训练对照。四个配置统一 global batch=512、32 轮；预计每组 917,504 张实际看图量，不承诺小预算结果继续成立。
  2. 再比较更大 batch 与学习率，按实际看图量对齐，并报告更新次数、验证 PSNR、重建细节、codebook perplexity、最终 DiT FID/KID；PSNR 不替代生成质量。
  3. VQ 可试数据初始化码本、EMA 码本更新、失活码重置；VAE 继续 KL 预热与较弱 KL 对照。先做单变量实验。

  5. Profiler 先量卷积、码本距离、DDP 通信与保存开销，再决定 channels-last / compile / 融合。JiT 的 1.70× 不能套用到卷积 VAE。
