已修复的实质问题

  1. VQ 损失尺度不一致：reconstruction 原来逐图求和，VQ/commitment 取均值。48px 的像素数系数为 6912，96px 为 27648。新默认采用 mean，sum 显式保留作旧对照；VAE 的求和 ELBO 约定不变。
  2. 固定 4×4 瓶颈及 48px 输出：支持原生 96px 与可配置网格；VQ 默认两层 encoder 在 48px 可保留 12×12、96px 保留 24×24。卷积/codebook 权重可严格继承；通道、码本大小需一致。init_checkpoint 只迁移权重，不恢复优化器。
  3. VAE 死参数：down_mu/down_logvar 从未进入 forward，已删除，解决无效参数和默认 DDP 梯度归约问题；旧权重仅忽略这四个已知冗余 tensor。
  4. 大 batch 内存与观测：码本距离保持 FP32，分块且不建梯度图；记录使用代码数/困惑度、全局看图量与实际更新次数。DDP 每次使用一个完整 16 GPU 组。
  5. 入口与数值一致性：CLI 与 API 共用核心训练器、固定留出集和完整模型配置；GAN 用 logits/softplus；修正预览归一化；停止把 Gaussian latent 直接喂 VQ decoder 当生成测试。DiT 从 checkpoint 读取实际网格和分辨率。

修复范围为 src/diffusion_demo、API 和 cmdline_train.py；根目录 app.py 对应历史实现，未替换其架构。旧 CPU 小预算诊断见 首轮审计报告。

验证、权重与下一步

31 项测试通过，包括双进程两轮 DDP、GAN 反传、原生 96px VQ-VAE→DiT→采样、旧权重加载和跨分辨率严格迁移。16 GPU 的 VQ48 与 VAE96 smoke 均通过。最佳 48px 权重已经 object storage 取回，SHA256 两端一致；本机 FP32 在相同 1,000 张验证图上重算 21.53 dB，数据 SHA256 已校验。

本地权重：runs/vae_gpu_20261025/best_model.pth（48px）、runs/vae_gpu_20261025/best96_model.pth（96px，24×24 latent，已校验 SHA256 并本机严格加载）；完整原始日志/配置/划分：runs/vae_gpu_20261025/。完整优化器 checkpoint 留在 shared filesystem。当前 autoencoder 没有精确续训入口，也没有 EMA。

下轮最值得做：码本数据初始化、EMA 码本更新或失活码重置（当前验证集用到 35/512 个码）；VAE 的 KL 预热/权重与 decoder 额外上采样层；按看图量定义的模型 EMA。大 batch 需同步比较学习率与更新次数；BatchNorm running buffers 不能直接照搬 JiT 的 EMA 逻辑。最终要训练 latent prior 再看生成网格和 FID/KID。核函数融合和 channels-last 先 profile，JiT 的加速倍率不能套用。
